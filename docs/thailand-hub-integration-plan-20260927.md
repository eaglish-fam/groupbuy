# 泰國三城整合頁：UI/UX 計畫

日期：2026-09-27。原始規劃記錄；互動地圖第一版已依後續授權實作，實際範圍見 thailand-hub-release-20260927.md。以下「現況」為改版前檢視。
目標頁：https://www.eaglish.store/trip/thailand/

## 目標與現況

讓第一次來的讀者能選出適合的城市、找到景點攻略，並了解如何把城市接成一趟旅行。國家頁負責選擇與串聯；各城市文章提供景點詳解、照片、地圖和當地日程。

正式頁檢視結果：

- 現在是導讀、三個文字連結、三張大型文章卡依序排列，曼谷先占據首屏，清邁與清萊需要往下找。
- 標題包含清萊，導讀尚未介紹清萊玩法。
- 沒有城市位置、城市比較與跨城安排，讀者需要自己打開三篇後再判斷。
- 國家頁的「精選行程」目前連到紐西蘭基督城，應改成泰國頁內的相關入口。
- 既有城市網址與文章可保留，整合重點放在國家入口與資料關聯。

## 建議方向：地圖選城市，照片選玩法

採用輕量可點地圖，搭配真實照片城市卡；照片和文字連結同樣可以直接操作。

第一屏的工作是回答「三座城市在哪裡、各自玩什麼、我要先看哪一個」。

### 桌面

- 短標題「泰國自由行，從哪一城開始？」及一句具體導讀。
- 左側為泰國輪廓地圖，曼谷、清邁、清萊各有地名與訊號點。
- 右側為選中城市的照片、三個玩法關鍵字、一段短介紹與「看城市攻略」連結。
- 城市切換按鈕保持可見，點地圖或按鈕都會切換相同的城市卡。點城市後先顯示內容，讀者再決定是否進入文章。
- 預設提供三城總覽／城市選擇提示，避免以預選曼谷讓另外兩城失去存在感。
- 首屏高度以地圖和照片能同時被理解為準，不做滿螢幕裝飾圖。

### 手機

- 地圖聚焦已收錄的泰北至曼谷區域，維持地理相對位置；完整泰國輪廓可作桌面總覽。
- 地圖下方固定位置顯示城市切換與對應照片卡，切換時保持卡片尺寸穩定。
- 點位與地名合併成至少 44×44px 可點範圍；清邁、清萊用錯開標籤與引線，避免互相遮住。
- 不依賴滑鼠 hover。鍵盤可以選城市，選取同時使用外框、文字與標記表達。
- 直接按城市名稱也能操作，不要求讀者理解或精準點擊地圖。

地圖採 SVG 與少量原生 JavaScript；開發時選擇允許再利用的地理資料並記錄授權。第一版不需要 Google Maps API、地圖金鑰或 3D 地球。

## 整頁順序

| 順序 | 區塊 | 讀者得到的幫助 |
| --- | --- | --- |
| 1 | 地圖＋三城照片入口 | 了解位置、辨認城市特色，進入攻略 |
| 2 | 三座城市怎麼選 | 以玩法、移動型態、雨天選擇做精簡比較 |
| 3 | 按玩法找景點 | 從「市集美食／動手體驗／親子活動／建築山景」挑選真實景點卡 |
| 4 | 城市怎麼接 | 展示單城、清邁＋清萊、曼谷＋泰北等可選組合與移動概念 |
| 5 | 我的泰國行程 | 精簡互動工具，依天數與城市產生一份跨城草案 |
| 6 | 行前問題與延伸閱讀 | 跨城交通、雨季安排等必要資訊，連回三篇完整攻略 |

第 3 區初始只顯示 4～6 張卡，透過分類切換與「看更多」逐步呈現。不一次把三篇景點全部攤開。

第 5 區放在後段；四字「行程規劃」懸浮入口跳到工具並移動焦點。沿用已確認的顯示／隱藏規則，避免遮住目錄或頁尾。步調名稱固定為「悠閒／緊湊」。

## 三城內容定位

| 城市 | 首要傳達的玩法 | 可用代表素材 | 規劃時要讓讀者理解 |
| --- | --- | --- | --- |
| 曼谷 | 市集、室內親子、河畔晚間活動 | SEA LIFE、恰圖恰、侏羅紀 | 市區與郊區分開安排，雨天也有室內選項 |
| 清邁 | 古城泰服、市集、手作 | 塔佩門全家照、紙園、Jing Jai | 市區與不同方向的郊區分日，部分市集有星期條件 |
| 清萊 | 藝術建築、花園、農場山景 | 白廟、Akha FarmVille、Lalitta | 城市周邊景點需搭車，山區活動另留時間 |

國家頁的主要閱讀按鈕先直達現有完整攻略，減少「國家頁→城市空泛總覽→文章」的重複選擇。城市索引網址保留，將來有多篇文章時承接專題與路線分類。

## 互動創意：把旅程接成一條線

用一條隨選擇更新的旅程線呈現「城市 → 移動 → 城市」。例如選清邁與清萊，就顯示兩城及中間的交通段；加入曼谷後，再呈現另一段跨城移動。

- 地圖負責選城市與瀏覽，旅程線負責理解先後和天數。
- 交通段要占用行程時間，不會因選三城就自動假設能順利玩完。
- 地圖上的連線是城市關係示意；詳細交通以查核過的資料和地圖入口呈現。
- 一次顯示一份草案。想比較其他組合，再切換選項。
- 每個城市日可展開當日重點，再點入該景點的完整介紹。
- 若所選天數不足，提供可操作的調整，例如少一城或多一天，避免塞滿不合理時間表。

第一階段先提供「清邁＋清萊」等固定路線示例，完成交通查核後發布。第二階段才讓天數與城市選擇真正驅動草案。

## 跨城工具的輸入與資料

基本輸入：旅行總天數、想去城市、入境／離境城市（可選尚未決定）、悠閒／緊湊。
需要核對市集星期時，再提供出發日期選填。

總天數必須納入抵達與離境；航班未知時，預留移動與休息區段，並讓使用者修改可用時段。

資料拆成城市、景點、城市間交通、可用路線範本。景點引用現有穩定 ID 與照片，不複製三份文案。交通記錄出發／抵達點、方式、規劃時間範圍、資訊來源和查核日。

已有三套城市 planner 的地點、時間、星期規則需要先整理成可引用的共用介面。國家頁的跨城組合和城市頁的某日安排分層處理，逐步支援雙向帶入；未完成狀態傳遞前，不顯示「已同步」等功能承諾。

首版可採已審查的路線範本與規則組合，使用者每次點擊不需要呼叫模型。模型可協助後台素材整理與草案審查。

## 視覺、圖片與搜尋

- 沿用奶油砂岩、紙白、暖棕與既有字體。橘紅用於地圖點、選取框與主要操作；活潑感以旅行照片與小幅互動呈現。
- 地圖有地理輪廓；拍照場景使用自有照片。城市圖片優先能辨認地點與玩法。
- 首屏主圖保留尺寸並優先載入，其餘圖片依位置延後載入；切換城市時先顯示已有縮圖或預留框，避免版面跳動。
- 城市標題、摘要、攻略連結與預設路線保留於靜態 HTML。JavaScript 強化選取，未啟用時仍有可閱讀的城市卡與路線。
- 保留國家／城市／文章網址、麵包屑與 canonical，國家頁回答「選哪座城市、怎麼搭配」，城市文章回答具體景點和日程。
- Google Maps 放在需要導航或查交通的位置；聯盟連結放在對應活動與方案內容中。

## 分階段交付

1. **泰國入口改版**：完成地圖、三城實景入口、精簡比較與正確導覽。可獨立上線，讓三篇內容更容易被找到。
2. **玩法與路線整合**：整理共用景點引用、分類卡與跨城交通；發布已核對的路線示例。
3. **跨城互動規劃**：加入天數、城市、進出點、步調與日期條件；呈現單份草案，支援修改與分享網址。
4. **使用者驗收與調整**：觀察城市選擇、攻略點擊、工具開始／完成、跨城調整情況。數據累積後再評估收藏或拖拉排序。

階段 1～2 已能交付完整可用的國家入口；第 3 階段另外驗收跨城排程邏輯。

## 驗收方式

- 新讀者能從第一屏辨認三城，並找到任一城市攻略。
- 桌面、390px 手機、鍵盤操作皆能切換城市，清邁與清萊點位沒有誤觸或重疊。
- 首屏照片先顯示；地圖和卡片有固定空間，切換無顯著跳版。
- 玩法分類能確實改變結果；未收錄的城市不生成虛構攻略。
- 跨城草案正確扣除交通、抵離日與休息，保留現有開放時間及星期條件。
- 讀者可從行程回到景點內容，再返回原選擇；分享網址可還原選項。
- 尚未完成的功能不出現在正式操作介面。
