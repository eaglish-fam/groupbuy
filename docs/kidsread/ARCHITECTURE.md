### ⓪ 入口總頁是主頁（Hiram 2026-11-23：「還是要有一個入口的總頁面…可以佔到 SEO 的排名，也可以得到好的 UX」）
- 架構是「主題總頁＋子頁」：總頁接最廣的搜尋（KidsRead、KidsRead 點讀筆、點讀筆推薦），子頁接長尾搜尋，彼此互連。
- 總頁要有：①這次開團的全部教材（篩選＋摘要＋價格區間，點開看重點、連到完整介紹）②怎麼買：點讀筆 3.0 單筆套組／單筆怎麼選、第一次買依年齡怎麼配 ③常見問題（輸出 FAQPage 結構化資料）④五篇子頁的導覽。
- 每個子頁上方有麵包屑「KidsRead 指南 › 這頁」、下方有系列導覽，都連回總頁；sitemap 的總頁優先度最高。
- 舊站三篇仍一對一 301 到①③⑤（內容最接近的頁），不全部導到總頁：全部導到同一頁，Google 容易當成軟 404，原本排名也接不過來。

標題、H1 和主打字是暫定的，等 projecteaglet.com 的 Search Console 匯出再依真實關鍵字定稿（見文末 SEO 段）。

## 資料

- `data/kidsread/catalog.json`：唯一的內容來源。
  - `pages`：六頁的 id、網址、標題、主打字、`redirectFrom`（舊站網址，只有①③⑤有）。建置程式和 sitemap 都從這裡讀。
  - 共 66 套教材，每套欄位：`id`、`name`、`home`、`guide`、`stage`、`lang`、`ages`、`tags`、`cover`、`blocks`（原文圖文）、`status`。
    - `home`：完整文字放哪一頁，`english`（③，46 套）或 `chinese`（⑤，20 套）。每套只有一個 home。
    - `guide`：另外出現在哪篇導讀，`reading`（②，12 套）、`zhuyin`（④，4 套）或 `null`。導讀頁只放摘要和連到 home 的連結。
  - 點讀筆那篇放在 `pen`；英文、中文兩篇的前言放在 `enIntro`、`zhIntro`。
  - `ages` 照原文「適用／適讀年齡」逐套手填（2026-11-23 依 Hugo 複核改版）：
    - `together`＝親子共讀、`alone`＝自主閱讀、`general`＝原文沒分；都是 `[最小, 最大]`，最大是 `null` 代表原文沒寫上限（例如「4+」「4–6⁺」）。`label` 是頁面顯示的字，例如「共讀 0–3 歲／自主 3–6 歲」。
    - 只抓書本的適讀年齡，內文另一項活動的年齡不算（例如 Math Machine 內文提到 3–4 歲看圖，主標是共讀 5–6／自主與心算 6+）。
    - 選書器的年齡籤是半開區間：0–2、3–5、6 歲以上；書的任一段和所選年齡重疊就列出。所以 0–2 歲不會推 Odd One Out（3–6⁺），兩套 Busy 系列在共讀和自主的年齡都找得到。
    - 原文沒寫年齡的 27 套是 `null`，頁面標成「年齡待補」，不自己猜。
  - `status`：依廠商給的 2026-11 品項（`data/kidsread/vendor-2026-11.json`）比對，`active` 40 套、`removed` 26 套；`removed` 不顯示，資料留著備查。
  - `variants`：這次可買的品項名稱（例如分輯、合購）；`seriesNote`：這次和舊文不同的地方（例如舊文寫第 1 輯，這次是第 2 輯）。
- 新品（`id` 以 `n` 開頭，16 套；n16 我的第一本認知圖典是 Hiram 的實體照才有、廠商參考頁沒列）：內容只寫廠商頁圖片上印的事實，不寫我們家的使用心得（還沒用過）。`isNew`、`photoSource`；`contentThin` 表示廠商圖只看得到內容物和書名，介紹比較短，拿到書再補。
  - 換輯的舊品（Dragon Masters、西遊記、KiDiDOC、與狗店長、IMAGINE IF、Jane Foster）在原文最前面加一段「這次開團的是…」（區塊有 `series: true`）。
  - `pen.products`／`pen.specs`：點讀筆 PLUS 3.0 單筆套組與單筆的內容物，入口頁「怎麼買」用。
- `data/kidsread/vendor-2026-11.json`：廠商頁擷取的品項對照（我們的 id ↔ 廠商品項）、這次沒有的舊品、新品清單。那是別團的頁面，價格只當參考，不寫進網站。
- `data/kidsread/migrated-posts.json`：三篇原文照順序的完整區塊，當作備查的原始檔（照片、圖說原樣保留）。
- 公開版不放：舊團購按鈕、舊檔期，以及英文篇前言的圖說「開團表單沒看到＝絕版停賣」（當期沒上架不等於停售）。catalog 裡這則圖說已清空，原文仍在 migrated-posts.json。
- `assets/kidsread/`：原文全部 224 張圖，原尺寸縮到最寬 1280px 的 WebP，去除相機資料。
- `docs/kidsread/extract-old-posts.py`：當時從舊站 HTML 抽出區塊用的程式。

## 選購清單與賣場連結（Hiram 2026-11-23 問：能不能在選物誌選好，到廠商頁購物車就有）
- 查過廠商平台（groupbuyforms）：購物車存在對方伺服器、綁對方網站的登入狀態，加入購物車要對方頁面發的安全碼；沒有「用網址帶入商品」或「貼上清單匯入」的功能。所以**從我們網站直接放進對方購物車做不到**；請客人在對方頁面貼程式碼之類的作法有資安疑慮，不做。
- 做得到的：對方頁面每個商品都有固定位置（`#item-<商品 id>`）。我們做「選購清單」：客人在選物誌挑好，清單裡每一項都有「到賣場加入」，點了直接跳到那個商品，只要選數量；也可以「複製清單文字」。清單只存在客人自己的裝置。
- 更好的作法（要 Hiram 跟廠商談）：請廠商在我們這團的賣場開「鷹家推薦主題包」（例如 0–2 歲、3–5 歲、6 歲以上各一包），選物誌推薦什麼，就一鍵連到那一包。參考賣場的別團就有 A–G 主題包，廠商做得到。
- 上線時：拿到我們這團的賣場網址後，用同一支擷取程式重新對照商品 id（`vendorItems`），網址放在設定裡。

## 前端做法（正式版）

- **建置程式**：`scripts/build-kidsread.mjs`（之後寫）讀 catalog，輸出六個靜態 HTML，每本書的完整文字都在 HTML 裡，Google 讀得到。
- **互動**：`blog/kidsread/kidsread.js` 用「狀態 → 重畫」的元件寫法做篩選、路線圖、書卡下方滑出、固定購買列，跟原型的做法相同；不載入 React 本體，手機開得快。
- **共用元件**：系列導覽列、篩選籤（至少 44px、選中有填色＋文字、結果數 aria-live）、書卡、下方滑出的書籍介紹（dialog）、固定購買列。
- **購買**：沿用 `articles/sheet-offer.js`。KidsRead 在 Sheet 是 2026/12/31～2027/01/06，按鈕依檔期自動切換：開團前「加入開團提醒」、開團中「選購」、結團後「目前沒有開放中的團購」。
- 寫作照 `docs/journal-editorial-guidelines.md`：不留 2023、2024 年的舊團購按鈕和舊檔期，不寫免責套語。

## UX 檢查（UI/UX Pro Max 規則）

- **可及性**：對比 4.5:1、可用鍵盤操作、焦點清楚、圖片都有說明。
- **觸控與回饋**：觸控目標 ≥44px，按下有回饋。
- **圖片**：WebP、延遲載入、預留尺寸。
- **版面**：手機優先、不橫向捲動、固定列不擋內容。
- **動態**：160–240ms，尊重 reduced-motion。
- **主題**：淺色、深色都要檢查。

## SEO：舊站三篇的排名怎麼接過來（2026-11-23 補）

舊站現況：projecteaglet.com 用 Yoast 和 Google Site Kit（已接 Search Console）。三篇都有自己的 canonical，彼此互相連結；最近一次更新是 2026-07，算是活躍頁面；中文教材那篇沒有 meta description。

### 會不會有影響：會，處理不好會掉
1. **重複內容**：新文章大量沿用舊文的圖文。舊頁還在、又沒有 301 或 canonical 的話，Google 只會挑一個版本排名，很可能是歷史比較久的舊站，新頁會排不上去。
2. **一個舊網址的排名只能交給一個新網址**：301 是一對一的。舊「英文教材」拆成②③、舊「中文教材」拆成④⑤時，要決定由誰接，另一篇從零開始。
3. **自家頁互搶**：②和③都寫英文教材、④和⑤都寫中文教材，標題太像會分散排名。

### 每本書的完整文字只放一個地方
- 英文書放③，中文書放⑤，而且要寫在靜態 HTML 裡，Google 才讀得到。
- 入口頁、②、④的書卡只放摘要。點開時從 catalog 載入完整內容，或連到 `③#書名`。
- 這樣同一段文字在站內只出現一次，各頁的主題也不重疊。

### 上線當天的順序
1. 新六頁上線，sitemap 一起更新。
2. 等對應的新頁都打得開、也確認舊站可以切換之後，才把舊站三篇設定 301 轉址到對應的新網址（WordPress 用 Redirection 外掛或 Yoast Premium 的轉址功能）。不先設轉址。
   - 如果沒辦法 301：舊頁留一段短介紹加連結，並在 Yoast「進階」欄把 canonical 填成新網址（免費版就有這個欄位）。
3. Search Console 分兩邊看，不混用：
   - 舊網址只在 **projecteaglet.com 的屬性**讀回（轉址生效、舊頁曝光下降）。
   - 新網址只在 **eaglish.store 的屬性**驗索引、送出請求索引。
   - 轉址至少保留一年。
4. 預期 2～6 週排名會有波動，之後由新頁接手。
