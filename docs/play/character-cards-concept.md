# 鷹家日常圖鑑：角色卡反向介面（GB-028，測試版）

依據：Hiram 2026-11-04 在 Grace 對話的需求（以產品為入口 → 反過來以「角色卡」為入口，參考八角遊戲化框架，先在 eaglish.store 掛一個「體驗／測試」入口）。
測試頁：`/play/`（noindex、不進 sitemap、首頁導覽最後一個連結「角色卡體驗（測試）」）。

## 一、核心想法：先認識人，再看需要

現在的網站是「商品牆」：使用者進來先看到商品，要自己判斷「這跟我有什麼關係」。
反向介面把順序倒過來：

```
角色（像我嗎？）→ 他的一天（我也會這樣）→ 某個時刻的麻煩（我懂）→ 剛好派得上用場的東西（原來可以這樣）
```

使用者不是在逛貨架，而是在陪一個人過日子。商品出現的那一刻，已經有情境、有理由，所以不像廣告。

## 二、角色卡長什麼樣子

每張卡有：

| 欄位 | 例子（黃詩涵） |
|---|---|
| 名字、年齡 | 黃詩涵，30 歲 |
| 身分 | 雙薪家庭的媽媽・會計，住桃園 |
| 一句話 | 女兒小米 14 個月，正扶著沙發學走路。 |
| 故事 | 夫妻都上班，晚上和週末是一家三口的時間；小米什麼都想摸、都想爬。 |
| 一天的行程 | 06:40 小米醒來想往下爬 → 07:30 早餐自己抓著吃 → 18:40 邊煮飯邊顧孩子 → 20:00 玩具散滿地 → 20:30 洗澡 → 22:30 終於輪到自己 |
| 每個時段的麻煩與需要 | 「學走路、跌坐時的柔軟地面」 |
| 對應商品 | Alzipmat、Playzu 地墊；MiToy 米積木；Done by deer、Meroware；PLAFARM；L'Ange；emma |
| 角色的反應 | 「她把積木疊起來又推倒，笑了好久，我終於把湯煮好了。」 |

名字：Hiram 舉例的「秀美」比較像 1960–70 年代出生的名字；30 歲（約 1995 年生）台灣女性常見名字是怡君、雅婷、詩涵、佳穎、宜蓁，所以第一版用「黃詩涵」。

## 四、八角遊戲化框架怎麼用（Octalysis 8 Core Drives）

| 核心驅動 | 在這個頁面裡 |
|---|---|
| 1 使命與意義 | 你是「鷹家補給官」，任務是讓別人的一天過得順一點。 |
| 2 進步與成就 | 每位角色有「安心值」；陪完一天得到徽章；稱號從見習補給官升到首席補給官；收藏冊 x/8。 |
| 3 創意與回饋 | 每個時段由你挑補給（部分時段有兩個選項），角色立刻回一句話；「做我的角色卡」自己選身分和煩惱，生成自己的卡和推薦。 |
| 4 擁有與佔有 | 角色收藏、徽章、補給清單、自己的角色卡（都存在自己的裝置）。 |
| 5 社交影響 | 「這就是我！」標記最像自己的角色；分享角色卡連結給朋友（手機用系統分享，電腦複製連結）。 |
| 6 稀缺與渴望 | **只用真的**：團購 Sheet 上真實的結束日期與倒數（3 天內轉成醒目顏色）。不做假倒數、不鎖內容。 |
| 7 好奇與未知 | 「抽一張角色卡」隨機遇見一個人；每天的時段逐段揭曉；中途隨機出現一張「意外事件」卡。 |
| 8 損失與避免 | 溫和使用：補給清單裡的商品會顯示即將截止／已結團。不做「不買就失去」的話術。 |

原則：第 6、8 項（黑帽）只用真實資料，避免讓使用者覺得被操弄；以第 1–4 項（白帽）為主，讓人因為「被理解」而停留。

## 五、資料與內容規則

- 商品只用品牌名對應團購資料：即時讀 Google Sheet「現正開團」（和首頁同一套 `catalog-core.js`），失敗時用 `config/catalog-snapshot.json`，並提示「開團狀態以首頁為準」。
- 開團中才出現「前往團購」，其他狀態只顯示狀態與生活筆記。
- 故事只寫角色的需求，不替商品寫規格、功效或價格；商品說明一律取自團購資料。保健食品的情境寫「先看標示、先問醫師或藥師」。
- 角色與故事是虛構的，頁面上有註明。不收集任何個人資料；進度、補給清單、暱稱只存在使用者自己的瀏覽器（localStorage）。
- 測試頁 noindex、不進 sitemap，不影響現有 SEO。

## 六、圖像

第一版角色是 SVG 插畫（同一套畫法、每位角色有自己的主色、髮型、配件，有孩子的角色旁邊會出現小孩），不需要外部圖檔、手機上也清楚；商品卡沿用網站既有的商品圖。之後如果要更精緻的角色插畫，可以請 Lydia／設計夥伴依同一份角色設定出圖，替換 `play/play.js` 的頭像即可。
