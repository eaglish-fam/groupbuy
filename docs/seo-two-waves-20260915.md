# 兩波 SEO：可讀目錄、內容連結與發布檢查

## 範圍與權限

此候選來自 `origin/main` 的 `5824f38`，分支 `feat/seo-two-waves-20260915`。Lydia 需求、Kira 工程；正式網站仍由 GitHub Pages 的 main 根目錄發布。此文件不是部署授權，不更改 Sheet、GA4 設定或排程。

## 已採用的設計

- 建置時從已儲存、可稽核的公開商品快照產生真正 HTML 卡片。一般使用者與搜尋引擎收到相同內容；不是隱藏關鍵字或只給爬蟲的版本。
- 快照只保留品牌、公開的長期介紹、分類、本站文章與圖片。不保留折扣碼、即時售價、庫存、購買連結、聯絡資料或私人備註。已結團但有實用文章的商品仍可閱讀；其他過期、未開團及日期不明項目不加入快照。
- 即時 Sheet 成功後，原有排序、篩選、圖片、詳情、收藏與購買前再確認流程照常接管。失敗時回到無購買承諾的商品介紹，清除各區塊舊購買入口，不把查詢失敗解讀成「沒有商品」。
- 無 JavaScript 的手機卡片不用依賴 masonry 測量；原始 HTML 已可閱讀、點文章。只有即時互動需要 JavaScript。
- 11 篇文章依真實主題建立延伸閱讀，連回商品介紹與 `/guides/`。`/how-we-select/` 說明實拍、廠商資訊、合作與使用 AI 的界線；不宣稱每件商品都親測。
- `content-index.json` 是公開文章清單，不含營運資料；每篇保留 canonical、商品名稱、意圖、日期與文章原始碼 SHA-256。供 Lydia 的生成前索引決策與內容回收使用。
- 本次建立主題群集與「下一篇需要哪些證據」的選題清單，不在資料不足時大量生成問題文、比較文；待研究與來源核對完成後才進入文章候選。
- 新文章與更新仍須通過既有來源／首圖／SEO 稽核。新增 sitemap 唯一網址檢查、站內連結與圖片稽核。可分享的篩選參數不是新 sitemap 網址。
- 只調整新增閱讀區塊與必要的窄螢幕溢出問題，不重新設計原本商品卡或文章首圖。

## 使用與驗收

```sh
npm run refresh:catalog   # 唯讀取得公開 Sheet，成功才替換快照
npm run verify           # 本地重建與離線回歸
node scripts/release-browser-audit.mjs
node scripts/seo-browser-audit.mjs
```

刷新失敗不能把快照覆蓋為空。平常 verify 不連外刷新，確保測試可重現。上線前另跑一次 refresh:catalog，檢查新內容差異再重新 verify。快照只提供介紹，不以刷新頻率保證即時開團資訊。

圖片稽核會區分阻擋與改善提示；檔案大小門檻是檢查線，不代表 Google 排名門檻。保留真實原圖；不要為了消除提示而讓 AI 重畫商品，或把首屏主圖一律 lazy-load。

2026-09-15 候選驗證：142 項單元／回歸測試、38 項既有購買／追蹤／快取瀏覽器檢查、62 項 no-JS／離線／行動閱讀檢查通過。SEO gate 檢查 24 個 sitemap 網址，0 項阻擋、37 項既有圖片格式／檔案大小／載入改善提示；未宣稱所有既有圖片都已最佳化。正式網站尚未發布。

## 新文章的索引身分

既有已對應商品卡的文章預設為 `product`。新增問題型、比較型或其他非商品文章時，需在 `config/content-articles.json` 的 `articles[slug]` 提供經審閱的 `mode`、固定 `intent`、確實涉及的 `productNames`。模式使用 `product / problem / comparison / scenario / explainer / use_care / longitudinal / budget_offer`；沒有獨立商品卡的文章 `productId` 為 null。建置不會把所有新文章硬套成商品文，也不會每次重建遺失原先核准的內容意圖。內容意圖相同時保留相同值，讓 Lydia 提出整併審閱，而不是改 slug 就視為全新內容。

## 正式發布與回復流程

網站候選通過、取得明確上線授權後才能發布。先部署網站，確認正式 `/content-index.json`、`/guides/`、`/how-we-select/` 與文章互連可用，再切換使用該清單的 Lydia 工作服務；只切 Console 不代表 Agency 已更新。

發布後執行 Lydia 的 14／28／90 日唯讀回收命令、URL Inspection 與商品維度 outbound 報告。這些數字是搜尋曝光／導出點擊，不是廠商成交；資料未提供不可補成零，也不能用一次排名變動推論演算法懲罰。季度回收只提出更新、合併或收錄檢視候選，不自動刪文章。

若要固定週期執行，須另行核准既有營運排程接入；本候選不自行建立 cron、heartbeat 或常駐 worker。

回復方式是經授權 revert 本候選發布提交，回到先前驗證的網站版本；Lydia 使用 Hub 保存的正式來源與 plist 回復流程，不重設資料庫、不改寫其他進行中的工作。
