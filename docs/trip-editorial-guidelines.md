# 鷹家遠行所：國家與城市旅行內容準則 v1.0

定案：2026-09-27。這是後續製作國家入口、城市攻略及行程工具的主要準則。泰國是第一組完成的參考案例：[國家入口](https://www.eaglish.store/trip/thailand/)、[曼谷](https://www.eaglish.store/trip/guides/bangkok-with-kids/)、[清邁](https://www.eaglish.store/trip/guides/chiang-mai-with-kids/)、[清萊](https://www.eaglish.store/trip/guides/chiang-rai-with-kids/)。沿用它們已確認的內容品質、奶油砂岩風格與可操作的行程模式；每個國家的城市數量、地理和景點資料重新決定。

## 一、讀者要完成的事

- 第一次進站的人，先選國家／區域／城市，再從照片理解玩法；即使沒看過鷹式一家的影片，也能獨立安排旅行。
- 國家頁回答「去哪個城市或區域、如何串接、需要幾天」；城市攻略回答「每站能玩什麼、何時能去、如何抵達、要留多久」。影片和家庭故事補充現場感，不接管文章順序。
- 每篇內容同時有可搜尋的具體問題與鷹式一家的第一手畫面。標題、導讀、H2、FAQ 直接回應讀者查找與決策，不靠關鍵字堆疊或空泛情緒文案。
- 目標不是列最多景點，而是讓讀者能刪選、比較並組合出自己的行程。

## 二、頁面分工與資訊架構

| 層級 | 任務 | 預設內容 |
| --- | --- | --- |
| 國家入口 | 讓讀者選區域／城市及旅行方向 | 國名、地理示意、可辨認地點的自有照片、城市／區域差異、按玩法挑景點、跨城選擇、行前問題、後置行程工具 |
| 城市入口（有多篇內容時） | 整理該城市不同主題與路線 | 城市定位、景點與攻略連結、實用路線；避免重複國家頁與完整攻略 |
| 城市攻略 | 讓讀者查清楚每站並組成當地日程 | 首屏、看圖挑景點、景點詳解、交通餐食與雨備、FAQ、後置行程工具、影片與延伸閱讀 |

國家入口的選單固定用「旅行總覽」等不含城市數量的名稱；國家上方用旗幟與英文國名，例如「🇹🇭 Thailand」。旗幟是輔助視覺，國名仍須是可讀文字。國家名稱、國旗、城市／區域與連結從該國資料設定產生，不把「三城」或「Thailand」寫成跨國共用文案。正文可誠實寫出當前收錄範圍，例如泰國現有三城。

地圖幫讀者理解相對位置，圖上點位和同等文字按鈕都能選擇城市；示意圖需標示為示意，不當成精準導航。國土形狀、離島與區域分布依目的地處理。城市多時先按區域或玩法收斂，景點卡初始約 4～6 張、再逐步展開；不要一次攤滿長串文字卡。預設總覽就能看見照片與可進入的攻略連結，無 JavaScript 仍可讀主要內容。

跨城工具只分配城市、天數與移動日；逐日景點的營業與星期規則由城市攻略處理。抵達、離境、跨城交通及休息時間都要占用天數；天數不足時提出可執行的調整。路線連到各城景點詳解，不虛構即時航班、車程或已同步功能。

## 三、城市攻略的固定閱讀順序

1. **首屏**：麵包屑、具體 H1、兩句以內的導讀、署名／更新日、能辨認地點或活動的自有實景主圖。
2. **看圖挑景點**：短小、接近方形的照片卡；放地名、主要玩法、建議停留時間，點擊到同頁詳解。景點多時先分組或漸進顯示。
3. **景點詳解**：每站先說它是什麼及值得玩的特色，再給實景圖、停留／營業／交通／雨備等分開的實用資訊、清楚的 H3／H4、Maps 與必要的預約來源。家庭故事一小段即可。
4. **旅行配套**：按區域整理交通、用餐、住宿、預約及整段雨備；回答讀者真正會問的 FAQ。
5. **互動行程試排**：放在 FAQ 後、完整影片和延伸閱讀前，保留 `#plan`；每次只顯示選中的日程。城市不同，可用天數與當日選項也不同。
6. **完整影片與延伸閱讀**：讓讀者想看現場時找得到影片，不要求先看影片才能使用文章。

曼谷篇仍有較早版本的前置行程工具；其照片、景點深度與語氣是參考，**後置工具以清邁、清萊及泰國入口的已確認版本為準**。後續調整曼谷時同步移位，新的國家與城市頁不沿用前置位置。

城市攻略手機版提供可隨時回跳的文章目錄，桌面提供側邊目錄。已確認手機頁籤為左側 36px、左內距 7px、右內距 3px、無箭頭；沿用 `/blog/reading-nav.js`，檢查焦點、目前閱讀位置與文字不被遮住。國家入口及攻略的右下四字「行程／規劃」入口點擊跳到後置工具並聚焦標題；工具、頁尾或目錄進入畫面時避免互相遮擋。按鈕可點範圍約 58×58px，包含安全區與降低動態效果設定。

## 四、文字與證據

- 標題寫地點、玩法及讀者能解決的問題；H3 暖棕色與左側細線和正文區分。先講玩法，再講真正影響選擇的提醒；一個限制說一次，盡量改寫成可採取的安排方式。
- 每站回答六件事：**是什麼、玩什麼、怎麼去、留多久、何時能去、雨天或特殊條件怎麼辦**。需要買票的，再說清楚票種、預約、集合點與取消條件。
- 公開頁只用有助選擇的「我們去過」「我們推薦」等自然說法；素材審核狀態、當年行程標籤、模型判讀及內部工作註記保留在資料文件。照片和影片能證明的實訪直接用在對應景點；延伸建議不能冒充實訪。
- 歷史照片、影片和 IG Reels 能證明當年的到訪與所見；目前營業時間、收費、票種與交通需另查官方／業者來源，並附核對日期。每站保留 Google Maps 入口，提醒出發前再看當日變更。Maps 的店名與營業時間仍需與官方公告交叉核對；兩者不一致時不猜測。
- 不由影片集數推定旅行天數，也不把不同日期的片段寫成連續一天。照片中無法確認的店名、文化身份、服務內容或動物福利狀態不可推斷。大量影格可用本機模型先整理候選，發表事實前仍以原片、照片文字、原始貼文與可靠來源核對。
- 優先用讀者能照做的句子，例如「週日市集排在傍晚」「先確定船班再排午餐」。刪除反覆的「不要、不能、不把」、自我解釋的邊界語，以及無資訊的排比與泛泛結語。

## 五、圖片、視覺與速度

色彩沿用奶油砂岩，不為每個國家套一組新的大型漸層或高飽和資訊面板：

| 用途 | 基準色 |
| --- | --- |
| 砂岩卡片 | `#f2eee5` |
| 奶油資訊區 | `#faf7f0` |
| 紙白底色 | `#fcfaf5` |
| 深可可文字 | `#494139` |
| 分隔細線 | `#dcd5c9` |
| H3 暖棕標題 | `#784b39`，700 字重，搭配 `#bb7658` 3px 左線 |

卡片文案短、空白適度、照片和景點相配；直式截圖或多張直式照片可並排，手機不拉成冗長單列。自有照片優先，需有來源、使用權、裁切與實際畫面的替代文字。平台評論照片不當官方素材；地圖插畫只說明地理概念，實景仍使用照片。影片擷取保留原片 ID、秒數與裁切紀錄，公開頁不露出私人路徑。

遵循 [圖片上稿規則](../trip/IMAGE_PIPELINE.md)：原圖留存、WebP 響應式尺寸、固定寬高、符合檔案大小預算。每頁只讓第一張主要旅遊視覺預載並用高優先權；其餘首圖降優先權、後段圖片延後載入。預載的 `srcset`／`sizes` 必須對上實際圖片，避免重複下載與首屏跳動。

## 六、資料與互動規則

- 每國、每城有自己的穩定 ID、景點資料、照片、來源和適用路線；國家頁、城市卡、攻略與工具引用同一地點身份。單一活動不重複建成另一個地理景點。
- 建議停留時間與實際營業時間分欄；營業、最後入場、固定休館日、市集星期、導覽／船班場次和跨區車程都進入排程。早上晚開的點不排早場，晚間活動要核對最後入場。
- 「悠閒／緊湊」是固定的步調名稱，不用「悠閒散步」。切換天數、步調、日期或景點要實際改變路線；同日不重複景點，換選項時保留仍合理的選擇。分享網址須能還原選擇；無 JavaScript 時仍有可讀的靜態路線或攻略。
- 票券和 affiliate 連結記錄來源及適用條件；舊影片價格、過期優惠及他站追蹤碼不能當現況。
- 選單、地圖點位與卡片可用鍵盤操作，選取狀態有文字或外框，不只靠顏色。手機避免橫向捲動，時間軸的點與線共用中心軸。

## 七、發佈前從讀者角度驗收

1. 不看影片，能從國家頁選到想去的城市／區域，並從照片辨認至少一種玩法。
2. 打開任一景點，能找到適合誰、停留、營業／星期、交通、雨備、Google Maps 和行前核對來源；實訪與推薦沒有混淆。
3. 選不同天數與「悠閒／緊湊」，路線確實變動；抵離與轉移日沒有被當成完整遊玩日，下午或晚間活動不違反營業／場次。
4. 手機先看到主要視覺，文章目錄、篩選、行程入口和照片都可閱讀／點擊；檢查鍵盤焦點、圖像替代文字及無 JavaScript 的基本內容。
5. H1、導讀、靜態攻略連結、FAQ、canonical、OG、Article／CollectionPage 與 BreadcrumbList 對同一正式網址和現有內容；不為分享狀態生成可索引的重複頁。
6. 執行 `npm run build:trip` 與 `npm run verify`，檢查圖片大小、內部錨點、來源、差異與 SEO 阻擋項。未核實的新景點或新票價不靠流程通過來替代事實查證。

## 八、套用到下一個國家

### Source bundle → owner → actual render 驗收

1. Project 素材包先列 stable source ID、檔案 hash、使用權與照片／原片定位；Terra 負責地點與現況查證、Alma 負責正文／alt／caption、Luca 負責媒體來源與輸出。缺件及現行價時未核項仍需保留，不由建置成功推定補齊。
2. Kira 將上述 owner 交付接到既有共用 renderer、卡片與行程資料；來源身份在正文、卡片、Maps、工具間一致，正文檔 hash 與實際渲染版本可回溯。不要只以「資料已交付」代替實際上稿。
3. 在獨立 noindex 候選頁核對 actual render：逐張看來源構圖、手機與桌機閱讀、目錄跳轉、分享還原、行程取捨及所有入口；執行 `build:trip`／`verify`，交精確可開 URL、來源／成品 hash 與已知缺件。Eliora 驗收讀者體驗，事實核對仍由來源 owner 確認；候選通過不等於獲准發布。

#### 宿霧／薄荷島案例回饋：來源覆蓋與首次操作

- 在已授權範圍盤完整原片的景點、餐廳、住宿及到達／機票需求，記錄實際辨認出的場景、時碼與未解身份。附件照片張數不是 coverage；不能因八張照片先到，就把影片裡可核對的餐廳、飯店或海上體驗排除。來源不足保留缺口，不以新店名、菜名、分館或房型猜測補齐。
- owner 交付後核對 manifest schema、readiness、清單長度、實體檔案與凍結 hash。本案 `luca-media-plan/4` 是 32 張（8 照片、24 影片畫格），含原15張 byte-identical 與新增17張；各版 lineage 保留。舊欄位 `coverage.excluded` 不是篩掉新組的指令，依本版 `expandedSections`、正文實際路徑與核准來源映射檢查覆蓋。不同案件數量依正式包，不把32寫成通則。
- 機票的普通 Skyscanner 官方入口與有證據的 affiliate URL 分開記錄。沒有正式 partner 身份及既有有效碼，就只用普通入口、`affiliate:false`，不造碼、不挪別家碼、不標 sponsored，不因入口出現而宣稱暫停中的機票雷達恢復。
- 完整原稿、alt／caption 和來源表以精確版本與 hash 匯入；核稿修正另存 revision，不靜默改 frozen source。舊事實 PASS 不覆蓋新內容，拒稿回條保留。Henann 只核到品牌時不猜分館或湊錯圖；Lila 的歷史體驗不直接成為工具中的可訂預設。
- 圖片驗收須包括真正的首次目錄點擊：在仍有 lazy 圖未下載的手機頁面只點一次，確認標題避開 sticky header，圖像 width／height 與 CSS aspect-ratio 已按真實裁切尺寸預留、沒有載入後跳位。再測桌機 fresh load 與 viewport 切換，親看實圖、圖說及成對 gallery；HTTP 200、檔案解碼或第二次點擊正常都不能替代第一次操作驗收。
- 混合橫直素材不能硬套等寬欄位再把卡片底部撐成大片空白。本案主題入口在手機採三條圖文列；桌面以來源比例分配欄寬。支持圖按原比例配對，混合橫直圖在手機分層、直圖限寬置中，不為等高裁人臉或拉伸。三張以上的故事圖組保留首張大主圖，尾張不留成孤立半格；逐組確認實際人物、字幕與場景可讀，再由 Eliora 視覺驗收。這是來源感知元件的適用方式，不把每篇固定成兩欄或三列。
- 單張直圖所在的 grid row 使用完整 `1fr` 軌道，再對 figure 限寬置中；成對軌道按比例正規化後分配，避免總 fractional units 小於一造成未分配空間。此修正保留原始來源比例與閱讀順序，仍須在實際畫面驗證。
- 總攻略回答跨島、行程與住宿區域選擇，房間、池區、上下樓等深度內容分到獨立住宿篇；先建好同包文章與回鏈，再啟用總攻略深度連結。實住紀錄與官方多館比較分開，品牌畫面不能借給未核定的分館。住宿篇沿用共用 shell、獨立 canonical、Article/Breadcrumb 與各自編號目錄，但不強塞總攻略的逐日 planner；只給適合任務的相關攻略連結。正文修訂另版、精確 hash 與來源表凍結，舊圖及舊正文不因搬移而刪除。

紐西蘭的現有入口在 `/trip/new-zealand/`，基督城／Akaroa 路線在 `/trip/new-zealand/christchurch/3-days/`。現有國家頁已收錄北島和南島多個地點；基督城路線的行程工具仍在 FAQ 前，是套用新準則時要調整的頁面。開始改版前先盤點城市與區域、自有照片、影片、來源和實訪狀態，決定讀者要先選「島／區域」還是「城市」。國家地圖與城市／區域卡依紐西蘭地理重新設計；具體停留時間、開放日、跨島交通和可用天數重新查核。沿用的是上述讀者任務、視覺語言、景點深度、後置工具和驗收方式，不直接移植泰國三城數量、路線或時刻。
