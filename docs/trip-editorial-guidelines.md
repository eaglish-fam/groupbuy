## 一、讀者要完成的事

- 第一次進站的人，先選國家／區域／城市，再從照片理解玩法；即使沒看過鷹式一家的影片，也能獨立安排旅行。
- 國家頁回答「去哪個城市或區域、如何串接、需要幾天」；城市攻略回答「每站能玩什麼、何時能去、如何抵達、要留多久」。影片和家庭故事補充現場感，不接管文章順序。
- 每篇內容同時有可搜尋的具體問題與鷹式一家的第一手畫面。標題、導讀、H2、FAQ 直接回應讀者查找與決策，不靠關鍵字堆疊或空泛情緒文案。
- 讓讀者能刪選、比較並組合出自己的行程。

| 層級 | 任務 | 預設內容 |
| --- | --- | --- |

| 城市入口（有多篇內容時） | 整理該城市不同主題與路線 | 城市定位、景點與攻略連結、實用路線；避免重複國家頁與完整攻略 |

國家入口的選單固定用「旅行總覽」等不含城市數量的名稱；國家上方用旗幟與英文國名，例如「🇹🇭 Thailand」。旗幟是輔助視覺，國名仍須是可讀文字。國家名稱、國旗、城市／區域與連結從該國資料設定產生，不把「三城」或「Thailand」寫成跨國共用文案。正文可誠實寫出當前收錄範圍，例如泰國現有三城。

地圖幫讀者理解相對位置，圖上點位和同等文字按鈕都能選擇城市；示意圖需標示為示意，不當成精準導航。國土形狀、離島與區域分布依目的地處理。城市多時先按區域或玩法收斂，景點卡初始約 4～6 張、再逐步展開；不要一次攤滿長串文字卡。預設總覽就能看見照片與可進入的攻略連結，無 JavaScript 仍可讀主要內容。

跨城工具只分配城市、天數與移動日；逐日景點的營業與星期規則由城市攻略處理。抵達、離境、跨城交通及休息時間都要占用天數；天數不足時提出可執行的調整。路線連到各城景點詳解，不虛構即時航班、車程或已同步功能。

## 三、城市攻略的固定閱讀順序

1. **首屏**：麵包屑、英文 eyebrow、H1 主標＋次標、兩句導讀、署名／更新日、一張主圖＋兩張輔圖。真實 width／height 選擇共用圖片分支：三直圖桌機原比例並排，橫圖左主右輔，混合圖按比例分欄；手機主圖在上、兩輔圖按比例並排。每張照片填滿自己的媒體版位，同時保留人臉、主要人物與重要景物，caption 放在照片下方。
2. **看圖挑景點**：3:2 短照片卡，桌面三欄、手機兩欄；放地名、主要玩法、建議停留時間，點擊到同頁詳解。長文放正文。
3. **景點詳解**：每站先說它是什麼及值得玩的特色，再給實景圖、停留／營業／交通／雨備等分開的實用資訊、清楚的 H3／H4、Maps 與必要的預約來源。家庭故事一小段即可。
4. **旅行配套**：按區域整理交通、用餐、住宿、預約及整段雨備；回答讀者真正會問的 FAQ。
5. **互動行程試排**：放在 FAQ 後、完整影片和延伸閱讀前，保留 `#plan`；每次只顯示選中的日程。城市不同，可用天數與當日選項也不同。
6. **完整影片與延伸閱讀**：讓讀者想看現場時找得到影片，不要求先看影片才能使用文章。

曼谷篇仍有較早版本的前置行程工具；其照片、景點深度與語氣是參考，**後置工具以清邁、清萊及泰國入口的已確認版本為準**。後續調整曼谷時同步移位，新的國家與城市頁不沿用前置位置。

城市攻略手機版提供可隨時回跳的文章目錄，桌面提供側邊目錄。已確認手機頁籤為左側 36px、左內距 7px、右內距 3px、無箭頭；沿用 `/blog/reading-nav.js`，檢查焦點、目前閱讀位置與文字不被遮住。國家入口及攻略的右下四字「行程／規劃」入口點擊跳到後置工具並聚焦標題；工具、頁尾或目錄進入畫面時避免互相遮擋。按鈕可點範圍約 58×58px，包含安全區與降低動態效果設定。

## 四、文字與證據

- 標題寫地點、玩法及讀者能解決的問題；H3 暖棕色與左側細線和正文區分。先講玩法，再講真正影響選擇的提醒；一個限制說一次，盡量改寫成可採取的安排方式。
- 每站回答六件事：**是什麼、玩什麼、怎麼去、留多久、何時能去、雨天或特殊條件怎麼辦**。需要買票的，再說清楚票種、預約、集合點與取消條件。
- 公開頁只用有助選擇的「我們去過」「我們推薦」等自然說法；素材審核狀態、當年行程標籤、模型判讀及內部工作註記保留在資料文件。照片和影片能證明的實訪直接用在對應景點；延伸建議不能冒充實訪。
- 歷史照片、影片和 IG Reels 能證明當年的到訪與所見；目前營業時間、收費、票種與交通需另查官方／業者來源，並附核對日期。已核實地點保留 Google Maps 入口，提醒出發前再看當日變更。只核到品牌、菜色或體驗，分館／當年業者尚未確認時，保留已核內容，省略未核地址、營業時間與 Maps；另列現行產品須明標「預訂參考」，不把它的集合點或條件套回舊實訪。Maps 的店名與營業時間仍需與官方公告交叉核對；兩者不一致時不猜測。
- 不由影片集數推定旅行天數，也不把不同日期的片段寫成連續一天。 不以貼文／影片發布日當成到訪日；到訪日期無法確認時，只寫有證據的先後關係或「那次」，不補日期。照片中無法確認的店名、文化身份、服務內容或動物福利狀態不可推斷。大量影格可用本機模型先整理候選，發表事實前仍以原片、照片文字、原始貼文與可靠來源核對。
- 優先用讀者能照做的句子，例如「週日市集排在傍晚」「先確定船班再排午餐」。刪除反覆的「不要、不能、不把」、自我解釋的邊界語，以及無資訊的排比與泛泛結語。

### 起稿尺度與整頁語意審查


固定順序：首屏與導讀 → 看圖挑景點 → 景點詳解 → 飲食、住宿、交通與雨備 → FAQ → 後置 `#plan` → 完整影片與延伸。先讓讀者知道去哪、玩什麼，再用工具串路線；影片不能取代攻略。

每站回答六問：是什麼、玩什麼、怎麼去、留多久、何時能去、雨天或特殊條件怎麼辦。先寫具體特色與玩法，接實圖、短家庭紀錄及分欄 facts；停留時間與營業時間分開。票券另寫包含項目、預約、集合、取消及適用條件。建議預留時間標為建議，交通、用餐、排隊另留；抵離與郵輪日另算。

家庭紀錄只用真實動作、選擇與轉折；無故事時直接寫玩法，不補情緒或對話。住宿保留有證據且影響選擇的入住經驗與實用資訊。新加坡 Amara 個案保留當次房型、人數、加費、換房及後續待遇的前後關係與官方入住資料；「三代訂房教訓」清單整塊刪除，不移到 FAQ 重講，也不把當次待遇寫成目前保證。

以下是起草上限，不是刪字驗收：H1 約 40 字、H2／H3 約 28 字；兩句導讀共 120 字；短卡只留名稱、玩法、時間，分別約 18／12／12 字；每站特色兩段共 220 字、家庭紀錄 160 字；單列 facts 70 字、FAQ 答案 140 字、工具提示 70 字；caption 45 字、alt 70 字。正式地名、身高安全條件、日期異動與完整事件因果需要超出時，分句或分欄保留必要資訊，內部記理由，不為字數犧牲準確。

### 圖片與所有公開文字一起審

正文每站一主兩輔，三張須是互補的場景、玩法或人物，不以重複影格或短卡湊數。依現行 IMAGE_PIPELINE 與滿版定稿選圖、保留 active picture、人物及來源比例；不自訂新比例，不補景、拉伸、遮字或以背景填空。Luca 管來源與輸出，Alma 親看原圖後寫 caption／alt，Kira 接線，Root 親看實際頁面。

caption 補充畫面，alt 描述可見人物、動作與場所，不塞關鍵字或臆測心理。迷宮圖是秀秀持棒、哥哥在前；水槽圖手部不清楚就寫站在水槽前；阿婆比讚不能改成她說了旁白中的話。換圖或裁切後重核文案、assetId 與來源，不能只沿用舊 caption。

Alma 親讀整篇，再逐項讀 H1／H2／H3、導讀、短卡、正文、facts、caption／alt、FAQ、planner 標籤與所有提醒，含 renderer 寫死的文字。檢查每句是否回答讀者問題、有新增資訊、符合證據，以及語氣是否自然；三代故事不寫成講課，段落不堆免責話。標題、卡片、Maps 與工具須指向同一地點，FAQ 不複製過期資料。

## 五、圖片、視覺與速度

色彩沿用奶油砂岩，不為每個國家套一組新的大型漸層或高飽和資訊面板：

| 用途 | 基準色 |
| --- | --- |
| 砂岩卡片 | `#f2eee5` |
| 奶油資訊區 | `#faf7f0` |
| 紙白底色 | `#fcfaf5` |
| 深可可文字 | `#494139` |
| 分隔細線 | `#dcd5c9` |
| H3 暖棕標題 | `#784b39`，700 字重，搭配 `#bb7658` 3px 左線 |

卡片文案短、空白適度、照片和景點相配；直式截圖或多張直式照片可並排，手機不拉成冗長單列。自有照片優先，需有來源、使用權、裁切與實際畫面的替代文字。平台評論照片不當官方素材；地圖插畫只說明地理概念，實景仍使用照片。影片擷取保留原片 ID、秒數與裁切紀錄，公開頁不露出私人路徑。

所有照片滿版：照片自己的四邊到實際畫面邊緣，grid gap 與文章外側留白不屬照片內部空帶。首頁國家入口、國家城市主圖、城市 main 優先選已核自有原照、使用同一地點身份的 3:2 衍生圖；有原照時不以影片帶字幕畫格取代。原照確實缺少時才選乾淨且能代表地點的已核畫格，記錄 fallback 原因。真正直式素材保留 source-aware paired 例外；support 與正文三圖按真實來源比例選 portraits／landscapes／mixed 共用分支。滿版與完整人物同時必要，不用不合比例的固定橫框 contain 留空，也不盲目 cover 切人臉。禁止奶油／黑色／模糊背景填空、生成補景、拉伸或遮罩；比例不合時調整版位或另選已核准素材。保存原始來源、active picture、焦點、dimensions 與裁切紀錄。caption 在照片外，不遮人物；不把旁邊遊客認作家人。首屏、短卡、正文及未來城市皆適用。

遵循 [圖片上稿規則](../trip/IMAGE_PIPELINE.md)：原圖留存、WebP 響應式尺寸、固定寬高、符合檔案大小預算。每頁只讓第一張主要旅遊視覺預載並用高優先權；其餘首圖降優先權、後段圖片延後載入。預載的 `srcset`／`sizes` 必須對上實際圖片，避免重複下載與首屏跳動。

### 國家手機圖組、完整字型與實際交通（2026-10-04 歐洲修正）

- 國家頁目的地選項在 1440／390／320px 維持同一橫列，至少 44px 高且完整可讀。檢查共用 nav gap、flex-basis 與真正手機 viewport 的 cascade；不能以較寬視窗、兩列或四列替代手機驗收。
- 地理圖組放在總覽照片與城市文字上方，使用紐西蘭同族的單一紙色 panel、地名卡、細 leader、紅點白邊與至少 44px controls；新國家仍由 Natural Earth／d3 的真實 bounds 與已核座標產生，不複製紐西蘭地形或假造道路。用既有 ISO 國家幾何區分目標國土與淡色鄰國，國界細線來自真實多邊形，不把 viewport 裁切邊當國界；小型國名標示不遮地名與點位。挪威本土為主、右上近旁圓形斯瓦巴 inset 在同一 panel；圓框上方明示「斯瓦巴離島框・非等比例距離」，完整收容城市與標籤，不用兩個等大灰框。全圖／本土／離島 controls 必須切換真實範圍、可回全圖；單一實際範圍不造多餘按鈕。每個 pin 與 label 都直接指向真實攻略／段落，不冒充城市 tab；荷蘭阿姆斯特丹與羊角村標籤分開且 leader 清楚，羊角村不另建成第二城市。保留鍵盤、狀態及 reduced-motion。
- 世界國家卡與國家城市卡用同一 `trip-travel-entry.mjs`／`travel-entry.css` 主次 CTA：暖棕 primary 進國家／攻略，secondary 挑玩法／景點；手機每項至少44px且集中配對。指南數取真實 guide/city IDs，region 取共用 catalog，不硬寫數量。實際 R24 projection 和通用 builder 都引用同一 renderer，不只更改生成 HTML。
- 全站標題使用同一完整繁中字庫，買物社／選物誌／遠行所首頁首次呈現不下載字型；進入其他頁或真正切換主畫面後低優先背景載入，先以宋體 fallback 呈現，完整解碼後才註冊兩個既有 serif aliases。sans 正文不改。移除自動 font-face／preload，保存官方 OFL、版本、hash 及實際 cmap，全站標題逐字核對；普通乾淨 repo build 不依賴私人 TTF／fontTools。驗證首頁零請求、慢網路／失敗可讀及跨頁已下載快取重用；無 worker 時不保證離頁前未完成下載可持續。
- 交通寫可用的實際路線、運具及已核對的編號／時間。SAS 直飛或經停路線使用本版官方資料與 Hiram 證言，當前班號不冒充家庭歷史訂位。刪除地圖下「依實際班次安排」等空泛航段，不將挪威國內航段標為國際線，不推論唯一航空公司、必須換機或同機保證。

WebKit 跨頁測試須核對實際字型 GET／payload，不只看 ResourceTiming。完整公開字型用 HTTPS 頁面本身的 Cache API 跨頁重用，不需 worker；儲存被拒或容量不足時退回 HTTP cache，文字仍立即可讀。不要為快取新增 Runtime、權限提示或永久儲存申請。

完整字型快取使用 `heading-serif-complete-500-v1`，不可落入既有 SW 的 `eaglish-` 清理前綴。舊 `eaglish-complete-heading-font-v1` 僅以指定 cacheName 的唯讀 match 查找，命中才複製公開字型至新快取；miss 不建立舊空快取、首頁不補抓。遷移 quota 失敗仍可解碼舊 bytes。驗證必須在隔離原生瀏覽器實際啟動原版 SW activate，核對舊版本清除、新字型保留與後續暖首頁零 GET；page request 和 SW 轉發事件分開記錄，不以 context raw 次數判斷重複下載。

## 六、資料與互動規則

### 標題層級與城市選擇焦點（2026-10-04）

- 已核城市攻略與國家頁共用 opt-in 標題系統：H1 深可可宋體；同一 H1 的次標較小、暖棕並可用 3px 左線，不另造 H2。正文 H2／H3／H4 依語意遞減；facts 標題保留暖棕左線，實訪小記錄保留較小可可標題。正文仍為 sans，地圖標籤與短卡維持其閱讀尺度，不套用正文大標尺寸。
- 冷載入先使用既有 Songti fallback，完整字型就緒後仍用同一 serif aliases；標題修正不新增字型載入或快取流程。
- 城市切換保留真實標題焦點、選取狀態與 live status；以 explorer 內實際 pointer／touch／keyboard 事件辨識操作，觸控／滑鼠不在程式聚焦的 H2 畫 UA 藍框，鍵盤保留可見暖棕焦點及必要捲動。不得全域移除 outline，也不只依賴 WebKit 的程式 focus-visible 推定。
- 城市 subtitle 逐欄檢查是否提供新資訊，不機械批次刪除或補空泛句。特羅姆瑟的「把戶外活動與兩座室內場館交錯安排。」已指定刪除，不移到 caption／FAQ；其他已核正文、故事與事實不改。

- 每國、每城有自己的穩定 ID、景點資料、照片、來源和適用路線；國家頁、城市卡、攻略與工具引用同一地點身份。單一活動不重複建成另一個地理景點。
- 建議停留時間與實際營業時間分欄；營業、最後入場、固定休館日、市集星期、導覽／船班場次和跨區車程都進入排程。早上晚開的點不排早場，晚間活動要核對最後入場。
- 「悠閒／緊湊」是固定步調名稱。以 ①天數、②步調、③日期分組，切換後實際更新已核實路線；單日切換保留相同語意。清邁和新加坡現行工具重新整理會重設，分享網址還原尚未提供；未來接線時另做驗證。城市只呈現已支援的操作與路線替換，無 JavaScript 時仍有可讀靜態路線。
- 票券和 affiliate 連結記錄來源及適用條件；舊影片價格、過期優惠及他站追蹤碼不能當現況。
- 選單、地圖點位與卡片可用鍵盤操作，選取狀態有文字或外框，不只靠顏色。手機避免橫向捲動，時間軸的點與線共用中心軸。

## 七、發佈前從讀者角度驗收

1. 不看影片，能從國家頁選到想去的城市／區域，並從照片辨認至少一種玩法。
2. 打開任一景點，能找到適合誰、停留、營業／星期、交通、雨備、Google Maps 和行前核對來源；實訪與推薦沒有混淆。
3. 選不同天數與「悠閒／緊湊」，路線確實變動；抵離與轉移日沒有被當成完整遊玩日，下午或晚間活動不違反營業／場次。
4. 手機先看到主要視覺，文章目錄、篩選、行程入口和照片都可閱讀／點擊；檢查鍵盤焦點、圖像替代文字及無 JavaScript 的基本內容。
5. H1、導讀、靜態攻略連結、FAQ、canonical、OG、Article／CollectionPage 與 BreadcrumbList 對同一正式網址和現有內容；不為分享狀態生成可索引的重複頁。
6. 執行 `npm run build:trip` 與 `npm run verify`，檢查圖片大小、內部錨點、來源、差異與 SEO 阻擋項。未核實的新景點或新票價不靠流程通過來替代事實查證。
7. 首屏每張實圖以 new tab → set viewport → goto 親自核對 1440／390／320px：無照片內部空帶、人物與人臉完整、caption 可讀且不遮主體、無橫向溢出。object-fit 名稱、尺寸計算與 HTTP 200 不能替代照片像素及構圖驗收；記錄 active source 與裁切判斷。
   本次新增首頁／索引入口照片也須逐張完成同尺寸滿版實圖與實際導流驗收。首頁國家入口、國家城市主圖、城市 main 使用已核 camera-first 3:2 衍生圖及真正共用 renderer／styles；不是借用文章標記而忽略首頁實際 cascade。來源仍按原圖與核准裁切追溯，真正直式素材採來源感知配對例外；support／正文保留原比例，不把所有圖片硬裁成 3:2。

#### 宿霧／薄荷島案例回饋：來源覆蓋與首次操作

- 在已授權範圍盤完整原片的景點、餐廳、住宿及到達／機票需求，記錄實際辨認出的場景、時碼與未解身份。附件照片張數不是 coverage；不能因八張照片先到，就把影片裡可核對的餐廳、飯店或海上體驗排除。來源不足保留缺口，不以新店名、菜名、分館或房型猜測補齊。
- owner 交付後核對 manifest schema、readiness、清單長度、實體檔案與凍結 hash。本案 `luca-media-plan/4` 是 32 張（8 照片、24 影片畫格），含原15張 byte-identical 與新增17張；各版 lineage 保留。舊欄位 `coverage.excluded` 不是篩掉新組的指令，依本版 `expandedSections`、正文實際路徑與核准來源映射檢查覆蓋。不同案件數量依正式包，不把32寫成通則。
- 機票的普通 Skyscanner 官方入口與有證據的 affiliate URL 分開記錄。沒有正式 partner 身份及既有有效碼，就只用普通入口、`affiliate:false`，不造碼、不挪別家碼、不標 sponsored，不因入口出現而宣稱暫停中的機票雷達恢復。
- 完整原稿、alt／caption 和來源表以精確版本與 hash 匯入；核稿修正另存 revision，不靜默改 frozen source。舊事實 PASS 不覆蓋新內容，拒稿回條保留。Henann 只核到品牌時不猜分館或湊錯圖；Lila 的歷史體驗不直接成為工具中的可訂預設。
- 圖片驗收須包括真正的首次目錄點擊：在仍有 lazy 圖未下載的手機頁面只點一次，確認標題避開 sticky header，圖像 width／height 與 CSS aspect-ratio 已按真實裁切尺寸預留、沒有載入後跳位。再測桌機 fresh load 與 viewport 切換，親看實圖、圖說及成對 gallery；HTTP 200、檔案解碼或第二次點擊正常都不能替代第一次操作驗收。
