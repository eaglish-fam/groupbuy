# 鷹家遠行所圖片上稿規則

版本：2026-10-12。沿用 [canonical 編輯流程](../docs/trip-editorial-guidelines.md)與[固定城市模板](../docs/trip-city-guide-template.md)，實際清邁為構圖基準；這是同一製作 pipeline 的媒體步驟。

城市名 → 主動盤點自家 IG／Facebook 輪播／相簿、原照與 YouTube 來源及權利 → 逐景點一主＋兩輔 → 官方事實與直接文案／alt／caption → 同模板接線 → 真實桌面／手機與首次跳轉 QA → 負責對話候選驗收 → 既有正式發布 → 負責對話正式頁驗收 → 真正 Ezra 版本去重 Telegram 回條。啟動範圍、草稿／預覽例外與發布權限依 [canonical 第八節](../docs/trip-editorial-guidelines.md)；本檔不另建製作流程。缺來源、畫面或事實保留具體缺件。

首屏固定 main + support-1 + support-2 身份；首頁國家入口、國家城市主圖、城市 main 優先已核自有原照 3:2 衍生圖，共用同一地點身份。原照缺少才用乾淨代表畫格並記錄原因；不選有無關對話字幕的主圖，不抹字、不生成補景。真正直式素材保留 source-aware paired 例外；support 與正文由真實 width／height 決定共用分支：三直圖桌面原比例並排，橫圖左主右輔，混合圖按來源比例分欄；手機上主圖、下兩輔圖按比例並排。2026-10-04 Hiram 滿版要求優先於歷史 g8 contain 固定框：每張實際照片填滿自己的媒體版位，同時保留完整人臉、主要人物與重要景物，caption 在照片下方。正文每景點三張互補實拍採 source-aware main+pair；短入口卡使用核准 3:2 裁切，桌面三欄、手機兩欄。歷史範圍：2026-10-04 歐洲修訂僅替換核准主圖與 metadata，保留當時 support、正文三圖、facts 與故事。後續任務依當次已核範圍處理。

照片內部的左右／上下空帶是缺陷，grid gap 與文章外側留白是正常版面間距。禁止背景顏色、黑色、模糊延伸、生成補景、拉伸或遮罩填空；也不為滿版硬切人臉。框比例不合時調整比例／排列或另選已核准素材。保留精確原始來源、active picture、focal point、dimensions、裁切與衍生 hash；多城市只替換資料及素材。

首屏親自驗收 1440／390／320px 的 Tailnet 首次開頁（new tab → set viewport → goto）：逐張確認像素滿版、人物／人臉完整、caption 清晰、不遮主體、無橫向溢出。CSS object-fit 名稱、尺寸或 HTTP 200 僅輔助，不能代替實圖構圖判斷；原始與 active source、裁切紀錄及截圖隨版本保存。

`npm run build:trip` 會先處理 `trip/assets/` 的原版 WebP，再生成頁面，最後檢查所有旅遊頁的圖片。這是發佈前的必要步驟；`npm run verify` 也包含它。

- 新照片先確認使用權、出處、裁切與替代文字，再放入 `trip/assets/`，使用不含尺寸後綴的 `.webp` 檔名。保留原始 JPG／PNG 供回溯，但頁面不要直接載入原圖。
- 建置會自動產生 640px、960px 版本。超過 1440px 的原版也會產生 1440px 桌機版；原版不覆寫。頁面使用 `srcset` 和 `sizes`。
- 共用建置規則 `scripts/trip-image-priority.mjs` 在頁首預載每頁第一張旅遊照片，並設為 `loading="eager" fetchpriority="high"`。預載與照片使用相同的響應式來源，避免下載兩種尺寸。其他首圖使用低優先權，後段照片使用 `loading="lazy" fetchpriority="low"`。瀏覽器仍會依視窗、快取與網路安排請求，這是優先權規則，並非等待首圖下載完成才允許下一張的串行佇列。
- 傳輸預算：640px ≤ 120 KB、960px ≤ 220 KB、1440px ≤ 400 KB。若圖片裁切或複雜度使壓縮仍超標，建置直接失敗，應檢查裁切／來源，不能跳過檢查直接上線。
- 這套檢查涵蓋 `trip/` 的目的地與攻略頁；社群分享用的 Open Graph 圖另行選擇與檢查。不要把公開頁面的圖片效能與原始素材檔混為一談。

目前紐西蘭與曼谷頁都使用響應式 WebP；`trip/assets/nz-farm.webp` 與 `nz-boat.webp` 的高解析原版保留作素材，頁面改載入 1440px 以下的版本。

### 自有社群照片與人物選圖（2026-10-12）

**已登入來源優先（2026-10-12 補正）。** 先確認既有瀏覽器中 IG／Facebook 的實際登入帳號，再查自家相關日期、目的地貼文、完整輪播與相簿。公開未登入頁的登入牆只代表該入口受限；須核對既有已登入入口後，才能判斷來源是否確實不可取得。記錄使用的帳號、來源頁與查找範圍，保留登入憑證於原瀏覽器。找到合適自家原照後，將實際採用的照片及對應版位列入交付驗收；僅搜尋過、僅列候選或最後全用影片畫格，都不能冒稱原照替換完成。個別景點缺合適原照時，保留已核畫格補充，與已採用原照分列。

Hiram 在馬來西亞文章指出：娘惹宅邸的雕花門面截圖把陌生旅客放在畫面前景，應改選合適照片。家庭擁有影片，只能說明素材來源；畫面中其他人的刊登判斷仍須獨立檢查。這是本網站的選圖標準，適用所有國家／城市的首頁入口、Hero、短卡、正文與分享圖。

1. **起稿時主動查自家 IG 和 Facebook。** 與已授權原始相簿、相機照片及影片一併盤點，實際查找目的地、景點、住宿相關的照片貼文、輪播各張及相簿；由既有官方帳號和來源索引確認帳號，不要求 Hiram 每次提供 permalink。兩個平台都須留下實際搜尋範圍、日期與可追溯貼文／相簿／圖片序號；同一張跨平台照片去重。搜尋引擎片段只能提供線索，選用前要開原貼文或相對應的授權原檔親看。
2. **合適自有照片優先於影片截圖。** 先選對應場所的家庭照片、建築、風景、食物與活動細節，再以已核影片畫格補足不同用途。可取授權原檔時用原檔；只有社群版本時核對清晰度、人物、地點和刊登來源，不能把社群介面截圖當文章照片。每站仍是一主兩輔三個互補畫面，不用同一張裁三次湊數，也不為來源比例硬換掉更合適的畫面。
3. **排除以陌生旅客為主體的照片。** 臉部清楚的陌生人特寫、前景遊客或以人群為主體的畫面，直接另選家人、景物或細節；尤其檢查其他家庭的孩子。工作人員、同行朋友也須有與本次刊登相符的授權依據才作人物主體。身份或依據不明，優先選其他畫面，不猜成家人。附帶的遠景人群僅在人物無法辨識、未成為焦點時保留，逐張記錄判斷；自家社群已公開不等於所有入鏡人物都適合再刊登。
4. **換圖解決問題。** 先查另一張原照或另一個乾淨畫格；允許有來源紀錄且保留主要景物的自然裁切。避免以打碼、模糊人臉、遮罩、生成消除人物或補景來保留原本不合適的構圖。滿版、人臉完整、來源比例與載入預留尺寸沿用既有圖片契約。
5. **缺件記錄具體範圍。** IG／Facebook 無法登入、貼文不可讀、解析度不足或實際找不到合適照片時，分別記錄阻礙與已查來源，先使用確實合格的其他授權素材完成可做部分。缺少現成 permalink 不構成略過社群搜尋的理由；未實查不得填「無照片」。核心來源或人物用途仍不明的候選不進發布包。
6. **兩道親驗。** Luca 交付每張選圖的場所／用途、來源 URL／相簿項目、原檔或畫格定位、權利依據、人物類型與排除／採用理由；Alma 隨換圖重核 caption／alt。Eliora 在實際版位逐張查看人物焦點與圖文對應，新增照片的來源與人物判斷都通過後才發布。機械檢測、素材所有權或過去已發布，均不能代替本次選圖判斷。

## 影片畫格的讀者視覺驗收

- 先逐幀確認是否有原片 letterbox；不要把編碼在原片內的上下黑條直接當成文章照片上稿。沒有黑條的畫格保持完整，不為統一比例硬裁。
- 只移除有證據的黑條，保留 active picture、字幕、人物與景物；不得用黑遮罩遮字幕、抹字、生成修補或拉伸實景。字幕若與黑條重疊須另選合適畫格或交回審核，不能犧牲內容換取外觀。
- 來源紀錄須保留原影片 hash、同幀 PTS／timebase、裁切座標與前後尺寸、衍生 hash；舊版保留。公開圖像修訂使用新 URL／variants，避免讀到舊快取。
- width／height 和載入前的 CSS aspect-ratio 預留空間以裁切後真實比例為準；不把 active picture 強制套回 16:9。驗收包含逐圖、手機／桌面實際頁面與尚未載入圖片時的首次目錄跳轉，不只檢查檔案存在。
